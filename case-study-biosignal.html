Case study / scientific computing

BioSignal Lab

A seeded machine-learning exercise using deliberately synthetic pulse-like waveforms to demonstrate feature extraction, subject-aware splits, and uncertainty reporting.

Python · NumPy · SciPy · scikit-learnSynthetic dataset onlyPublished on GitHub

Scope: These are artificial signals, not real ECG or EEG recordings. This project is not a medical device, clinical model, or validation study.

01 / Research question

Can a reproducible demo exercise the right evaluation habits?

The repository is built to test an analysis workflow, not a biomedical hypothesis. It generates labeled simulated subjects, extracts simple waveform and peak features, trains a modest classifier, and tests that segments from the same synthetic subject do not cross the train/test boundary.

02 / Pipeline

Keep the grouping through evaluation.

02FeaturesStatistics + peak timing
→
03Group splitSubjects kept apart

04EvaluationMetrics + subject bootstrap
  • Seeded generation makes the example repeatable.
  • GroupShuffleSplit assigns whole simulated subjects to one side of the split.
  • The Brier score measures probability prediction error; a lower value alone does not prove better calibration.
  • Bootstrap intervals resample held-out subjects as clusters so each subject’s segments stay together.

Method references: GroupShuffleSplit documentation and scikit-learn calibration guide.

03 / Seeded example result

One reproducible run, clearly labeled.

With seed 17, the generated example contains 360 synthetic segments from 30 simulated subjects. The held-out split contains 96 segments from 8 subjects and has zero subject overlap with training.

04 / Limitations and next steps

A pathway to real data needs provenance first.

The generator intentionally simplifies physiology and makes its labels from its own rules. It cannot represent clinical populations, acquisition artifacts, or real diagnostic uncertainty. No real dataset is bundled, and no clinical claim is made.

A future real-data study would first need to verify the dataset’s access terms, licensing, cohort and outcome definitions, participant grouping, and evaluation protocol. Only then would it make sense to choose baselines and report results.
